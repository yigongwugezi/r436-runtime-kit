## 一、设计原则

1. **只展示 Agent 实际产出的数据。** 不凭空设计后端不存在的功能。文档里每一条字段都对应某个 Agent 的 `run()` 返回 dict 中的真实 key。

2. **对话即主界面。** 学生通过对话驱动一切。GUI 面板是对对话中结构化产出的可视化呈现，不是替代对话。

3. **Agent 的成熟能力要外显。** DiagnosisAgent 的证据链、PlannerAgent 的复习调度、ReviewAgent 的质量门禁——这些都是实打实的功能，必须在界面上让学生感知到，不能闷在 final_reply 里变成一段文字。

4. **置信度和来源要透明。** 凡是 Agent 产出带有 `confidence` 和 `source` 的，界面上必须可见。学生需要知道哪些是系统推断的、哪些是他自己说的。

5. **不做后端没有的 Agent。** 交互文档旧版里的"代码沙箱智能体""动画渲染智能体""语音合成智能体"——后端没有，不设计。

## 二、信息架构与页面结构

### 2.1 页面树

```
EduAgent
├── 学习主页        ← 默认着陆，中间展示区 + 右侧对话区
├── 学习画像        ← ProfileAgent 9 维浮层面板
├── 学习诊断        ← DiagnosisAgent 薄弱点 + 证据链（全屏页）
├── 学习路径        ← PlannerAgent 阶段路径 + 复习调度（全屏页）
├── 学习报告        ← ReviewAgent 审查结果聚合（全屏页）
└── 对话区          ← 始终可见的右侧面板（桌面端）/ 全屏（移动端）
```

### 2.2 桌面端布局（≥1440px）

```
┌──────────┬────────────────────────┬──────────────┐
│ 左侧导航  │                        │  右侧对话区    │
│          │     中间内容展示区       │              │
│ 📚 主页   │   （资源/路径/诊断/     │  对话消息列表  │
│ 👤 画像   │    报告等面板在此展开）  │              │
│ 🩺 诊断   │                        │  输入框       │
│ 🗺️ 路径   │                        │              │
│ 📊 报告   │                        │              │
│          │                        │              │
│ 240px    │     flex-1             │  400px       │
└──────────┴────────────────────────┴──────────────┘
```

### 2.3 对话与面板的联动关系

核心交互规则：**对话中 AI 的结构化产出，在中间展示区以卡片/面板形式呈现。学生可点击卡片跳转到对应的全屏页。**

| AI 在对话中产出了什么 | 中间展示区呈现什么 |
|:---|:---|
| `profile`（画像任一维度被提取/更新） | 画像维度更新通知卡片，点击→画像浮层 |
| `diagnosis`（薄弱点诊断结果） | 薄弱点列表卡片，点击→诊断全屏页 |
| `learning_path`（学习路径） | 路径概览卡片，点击→路径全屏页 |
| `resources`（学习资源） | 资源内容卡片直接在中间区渲染 |
| `questions`（练习题） | 练习卡片在中间区渲染 |
| `grading_result`（批改结果） | 批改详情卡片，含错误分类 |
| `review`（质量审查结果） | 质量摘要标签（passed/warning/blocked） |

## 三、对话区——主交互界面

### 3.1 对话区结构

```
右侧对话区（400px，始终可见）
│
├── [头部] 高度 56px
│   ├── "EduAgent 学习助手"
│   └── 当前活跃智能体指示器
│       ├── 单 Agent 运行时："🟢 PlannerAgent 正在规划学习路径..."
│       ├── 多 Agent 顺序执行时："🔄 正在生成学习资源(4/6)..."
│       └── 空闲时：不显示
│
├── [消息列表] flex-1，overflow-y: auto
│   ├── 学生消息：右对齐，#6366F1 背景，白色文字
│   ├── AI 文字消息：左对齐，白色背景，Markdown 渲染
│   └── AI 结构化消息（特殊卡片类型，见 3.2）
│
├── [上下文指示条] 条件显示
│   └── 当学生选中文档内容或当前页面有关联资源时显示
│
├── [建议指令] 条件显示
│   └── 3-5 个基于上下文的快捷指令标签

    ├── 📎 上传文件按钮
    └── 发送按钮（有内容蓝色实心，无内容灰色禁用）
```

### 4.3 维度卡片的三种状态

| 状态 | 外观 | 触发条件 |
|:---|:---|:---|
| 已填充（高置信度） | 完整显示 value + score + evidence，绿色置信度标签 | confidence ≥ 0.7 |
| 已填充（低置信度） | 完整显示，黄色置信度标签，附"可能需要补充"提示 | confidence < 0.7 |
| 未填充 | 灰色卡片，"待补充"占位文字，点击→跳转对话引导填写 | value 为 "待补充" 或 score = 50（默认值） |

## 五、学习诊断——DiagnosisAgent

### 5.1 数据来源

DiagnosisAgent 产出结构：

**薄弱知识点列表** (`weak_knowledge_points` / `weak_topics`)：
| 字段 | 含义 |
|:---|:---|
| `name` / `topic` | 知识点名称 |
| `priority` | high / medium / low |
| `reason` | 为什么判定为薄弱 |
| `confidence` | 置信度 |
| `evidence` | 证据列表 |
| `source` | 证据来源（behavioral/user_report/profile/prior_diagnosis/...） |
| `difficulty` | 知识点难度 |
| `prerequisites` | 前置知识点 |
| `recommended_stage_id` | 匹配到的学习路径阶段 |
| `recommended_resource_ids` | 匹配到的学习资源 |
| `next_actions` | 建议行动 |

**证据链** (`evidence_chain`)：
| 字段 | 含义 |
|:---|:---|
| `source` | 证据来源 |
| `signal` | 信号描述 |
| `related_knowledge_point` | 关联知识点 |
| `weight` | 权重 |
| `reason` | 原因 |

**掌握度矩阵** (`mastery_levels`，自适应诊断模式)：
| 字段 | 含义 |
|:---|:---|
| `name` | 知识点名称 |
| `score` | 0-100 掌握度分数 |
| `level` | 未学 / 初步 / 熟练 / 精通 |
| `confidence` | 置信度 |
| `trend` | stable / improving / declining |
| `knowledge_type` | memory / concept / procedure / design |
| `error_type` | structural / deviation / application / metacognitive |
| `stage` | 7 阶段掌握度环路位置 |
| `review_interval_days` | 艾宾浩斯建议复习间隔 |
| `evidence_count` | 证据数量 |

**全局标记**：
| 字段 | 含义 |
|:---|:---|
| `needs_more_evidence` | 是否需要更多证据 |
| `risk_flags` | 风险标记列表 |
| `confidence` | 整体诊断置信度 |

## 十一、异常与边界

### 11.1 Agent 执行失败

| 场景 | 前端表现 |
|:---|:---|
| Agent `run()` 抛异常 | 对话区显示"XX 智能体执行异常"，提供"重试"按钮 |
| Agent 返回 `quality_status: "fallback"` | 相关内容卡片显示灰色"fallback"标签，提示"该内容为规则生成的默认版本，可能不够精准" |
| LLM 不可用 | 对话区提示"当前使用离线模式，回复质量有限"，所有 Agent 产出标注 source: rule_based_fallback |

### 11.2 ReviewAgent 阻塞

| quality_status | 行为 |
|:---|:---|
| passed | 资源正常展示 |
| warning | 资源正常展示，但卡片头部有黄色警告标签，hover 显示具体问题 |
| blocked | 资源不展示，对话区显示"XX 资源因质量问题（具体原因）被拦截，正在重新生成..." |

### 11.3 DiagnosisAgent 证据不足

| needs_more_evidence | 行为 |
|:---|:---|
| true | 诊断页顶部显示"证据不足"横幅，建议发起诊断测试；薄弱点列表仍然展示但置信度偏低 |
| false | 正常展示 |
