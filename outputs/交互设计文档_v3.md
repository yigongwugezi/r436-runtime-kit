## 第一章 设计总纲与全局框架

### 1.1 产品定位

基于 9 个专业智能体协同工作的对话式个性化学习系统。学生通过自然语言驱动，系统自动完成画像构建、薄弱诊断、路径规划、资源生成、练习批改、质量审查。

### 1.2 核心设计理念

1. **对话即界面。** 自然语言是最高优先级的交互方式，GUI 是对话中结构化产出的可视化呈现，不是替代对话。
2. **智能体能力外显。** 每个 Agent 的核心能力（证据链追溯、置信度评估、质量门禁、艾宾浩斯调度）必须在界面上被学生感知到。这些是系统的核心价值，不能闷在后端。
3. **先预览，再确认，后执行。** 大粒度操作（全流程生成）必须先展示计划让学生确认，不能黑盒跑完直接吐结果。
4. **过程可见，状态透明。** 多 Agent 协同执行时，学生能看到当前在哪个阶段、哪些已完成、是否有重试。
5. **全操作可追溯。** 所有 Agent 产出标注来源（user_input / inferred / llm_generated / diagnosis / behavioral）、置信度（0-1）、证据链。学生知道每一条信息"是谁说的、为什么、可信度多高"。

### 1.3 屏幕适配策略

| 断点 | 布局 |
|:---|:---|
| ≥1440px | 三栏：左侧导航(240px) + 中间展示区(flex-1) + 右侧对话区(400px) |
| 1024-1439px | 两栏：左侧导航(64px 图标) + 右侧(展示区与对话区上下分屏) |
| <1024px | 单栏：底部 Tab 导航，展示区全屏，对话通过 FAB 浮层唤起 |

### 1.4 9 个智能体一览

| Agent | 中文名 | 能力 | 产出 |
|:---|:---|:---|:---|
| ConversationAgent | 对话智能体 | 意图分类、自然语言对话、子 Agent 调度、最终回复汇总 | reply, action, intent, facts |
| ProfileAgent | 学习画像智能体 | 从对话中提取/更新 9 维学习画像 | profile(9维), 每维含 value/score/confidence/evidence/source |
| KnowledgeAgent | 知识检索智能体 | RAG 语义搜索 + 课程目录回退 | knowledge_context(知识点列表含 priority/difficulty/excerpt) |
| DiagnosisAgent | 学习诊断智能体 | 多源证据融合诊断、贝叶斯掌握度估计、自适应诊断测试 | weak_topics(含证据链), mastery_levels, risk_flags |
| PlannerAgent | 路径规划智能体 | 4 阶段 LLM 管道 + 艾宾浩斯复习调度 + 动态调整 | learning_path(stages), review_tasks, stage_rationales |
| ResourceAgent | 资源生成智能体 | 6 类资源生成 + RAG 证据锚定 | resources(含 quality_status/generation_mode/evidence) |
| QuestionAgent | 试题生成智能体 | 5 类题型 + 自检 + 难度校准 + 去重 | questions(含 difficulty/quality_status) |
| GradingAgent | 自动批改智能体 | 4 维评分 + 5 类错误分类 + 自动追进行动 | grading_result(含 dimension_scores/error_type/auto_actions) |
| ReviewAgent | 质量审核智能体 | 12+ 项质量检查 + 防幻觉校验 | review(含 quality_status/checks/anti_hallucination) |

## 第二章 全局导航与信息架构

### 2.1 设计理念

本系统是**对话驱动**的多智能体学习平台。学生通过右侧对话区控制一切——画像构建、诊断、路径规划、资源生成、练习批改——所有操作由 ConversationAgent 总控调度，9 个专业 Agent 在后台协同。中间展示区是对话中结构化产出的**可视化呈现**，不替代对话，但可在对话之外独立浏览和深入查看。

三栏核心规则：
- **右侧对话区（400px）**：始终可见。唯一的学生输入通道。Agent 的进度、结果、确认请求都在这里呈现。
- **中间展示区（flex-1）**：对话产出的资源、诊断、路径地图、练习、报告在此展开。可脱离对话独立浏览。
- **左侧导航栏（240px）**：全局导航 + 快捷入口 + 画像状态总览。不是操作中心——操作都在对话里。

### 2.2 屏幕适配策略

| 断点 | 布局 |
|:---|:---|
| ≥1440px | **标准三栏**：左导航(240px) + 中间区(flex-1) + 右对话(400px) |
| 1024-1439px | **两栏**：左导航收为图标模式(64px，hover展开文字标签) + 中间区与对话区上下分屏(各50vh) |
| <1024px | **单栏层叠**：底部TabBar(4项) + 内容区全屏 + 对话通过右下FAB(56px)浮层唤起(占85vh) |

```

  knowledge_type(memory/concept/procedure/design),
  error_type(structural/deviation/application/metacognitive),
  stage,             // diagnostic→explain→feynman_check→practice→error_diagnosis→review→completed

```


## 第十三章 异常状态与边界情况

### 13.1 Agent 执行失败

| 场景 | 表现 |
|:---|:---|
| Agent run() 抛异常 | 进度面板该步骤显示 ❌ + 错误原因；后续步骤继续 |
| 关键 Agent 失败(PlannerAgent/ResourceAgent) | 进度面板显示 ❌ + "是否重试？" |
| LLM 不可用(全 Agent 回退 rule_based) | 对话区顶部黄色横幅"当前使用离线模式，生成质量有限"；所有产出标注 source: rule_based_fallback |
| Agent 超时 | 进度面板显示 ⏱️ + "已超时，使用部分结果" |

### 13.2 ReviewAgent 阻塞

| quality_status | 行为 |
|:---|:---|
| passed | 正常展示 |
| warning | 正常展示+黄色标签，对话区提示具体问题 |
| blocked | 内容不可用，自动触发重试(最多2次)，重试耗尽后显示降级选项 |

### 13.3 网络异常

| 场景 | 表现 |
|:---|:---|
| 流式输出中断 | 已输出部分保留+末尾"..."；自动重连；超时显示[重新生成] |
| 请求发送时断网 | 消息气泡右侧红色感叹号，hover→"发送失败，点击重试" |
| 全站离线 | 顶部黄色横幅"当前处于离线状态"，缓存内容可查看 |

### 13.4 空状态

| 场景 | 设计 |
|:---|:---|
| 无画像 | 引导对话自动开始，头像光环 0% |
| 无诊断 | "还没有诊断数据，发送'帮我诊断'或完成一些练习后自动生成" |
| 无学习路径 | "还没有学习路径，在对话中说'帮我规划'即可" |
| 无资源 | 空状态引导+快捷生成入口 |
| 无练习记录 | "还没有练习记录，去做几道题吧" |
| 对话为空 | 欢迎消息+快速开始卡片 |

### 13.5 边界

| 场景 | 处理 |
|:---|:---|
| 对话消息 >500 条 | 自动总结前 200 条为摘要，保留最近 300 条 |
| 同时触发多个资源生成 | 排队，进度面板显示队列顺序 |
| 学生在执行中发新消息 | 新消息排队，等当前流程完成（或取消当前流程） |
| 学生在预览阶段取消 | 已产出的画像/诊断/路径预览保留，资源不生成 |

## 第十四章 后端改造需求清单 🆕

> 前端设计不被后端现状约束。以下是实现本文档交互所需的后端改造。

### 14.1 编排层（最高优先级）

| 改造项 | 说明 |
|:---|:---|
| **LangGraph astream 模式** | `run_pipeline` 中 `full_workflow` 路径从 `ainvoke` 改为 `astream(stream_mode="updates")`，每个 Agent 节点完成后推送事件 |
| **Agent 事件协议** | 定义 `AgentProgressEvent` 类型：`{node, agent_name, status(started/completed/failed/retrying), result_summary, duration_ms}` |
| **预览-确认机制** | `full_workflow` 和 `plan` 意图不直接跑完。先跑到 PlannerAgent 路径预览 → 等学生确认 → 再跑 ResourceAgent。Orchestrator 增加 `confirm` 和 `cancel` 信号处理 |
| **取消机制** | Orchestrator 支持接收取消信号，中断正在执行的 Agent 链 |

### 14.2 智能体层

| Agent | 改造项 | 说明 |
|:---|:---|:---|
| ConversationAgent | 增加 `mode="preview_request"` | 大请求时先生成确认交互，而非直接执行 |
| ProfileAgent | 增加事件驱动增量更新 | 收到 GradingAgent 错误反馈后自动更新 error_patterns 维度 |
| DiagnosisAgent | 暴露 `diagnostic_phase` 状态 | 自适应诊断三步中每一步完成推事件给前端 |
| PlannerAgent | `adjust` 模式触发自动化 | GradingAgent 发现连续错误时，Orchestrator 自动调 PlannerAgent.adjust，生成调整建议卡片 |
| ResourceAgent | 暴露批次进度 | 每批次完成推事件（已完成/总数） |
| ReviewAgent | 审查结果实时推送 | 不要等全部跑完，审查完一个资源就推一个 |

### 14.3 新增模块

| 模块 | 说明 |
|:---|:---|
| **事件总线** | Agent 执行进度、错误、审查结果都通过统一的事件通道推送到前端（SSE/WebSocket） |
| **任务状态管理** | 每个 pipeline 执行有唯一 run_id，前端可以通过 run_id 查询当前状态、取消执行 |
| **Agent 元数据接口** | `GET /api/agents` 返回所有注册 Agent 的 id/name/能力描述/当前状态，前端用于渲染智能体指示器 |
