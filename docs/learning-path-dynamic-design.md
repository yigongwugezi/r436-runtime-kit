# 学习路径页面 — 动态交互方案

## 0. 当前问题总结

| 现状 | 问题 |
|------|------|
| 路径是一次性生成的静态文档 | 用户学快了/学慢了/卡住了，路径纹丝不动 |
| 后端 adjust 闭环已实现但前端不感知 | 结构变化（增减阶段、调整天数）用户看不到 |
| 页面是"只读浏览"模式 | 没有进度驱动、没有调整日志、没有主动建议 |
| 练习与路径脱节 | 做错10道题，路径没有任何反应 |
| 时间约束死板 | 剩余天数变了，各阶段权重不重新分配 |

## 1. 设计原则

1. **导航仪而非课表** — 路径始终反映"当前最优路线"，不是"一开始定的计划"
2. **变化可见** — 每次调整都要让用户知道：发生了什么、为什么、影响是什么
3. **一键操作** — 用户不需要理解 agent 机制，日常操作 ≤ 1 次点击
4. **渐进披露** — 默认展示概览，需要时展开细节，不信息过载

## 3. 各区详细设计

### 3.1 左侧：路径阶段列表

每条阶段卡片包含：

```
┌──────────────────────────────────────────────┐
│ 🔵 阶段3：极限计算                   3天→已学1天│
│ ┌──────────────────────────────────────────┐ │
│ │ ████████░░░░░░░░░░ 45%  掌握度           │ │
│ └──────────────────────────────────────────┘ │
│ 包含：2章 / 4节 / 6个知识点                  │
│ 预计完成：Day 7 (还剩2天)                     │
│                                              │
│ ▸ 极限定义与性质         ☑ 已完成             │
│ ▸ 夹逼定理与单调有界      ☐ 学习中             │
│ [展开全部章节]                                │
│                                              │
│  ⚠ 检测到4道连续错误 → 已插入回顾任务         │
└──────────────────────────────────────────────┘
```

**状态标识**：
- 🔒 未解锁 — 前置阶段未完成
- 🔵 当前进行中 — 带进度条
- ✅ 已掌握 — mastery ≥ 85%
- ⚠ 遇到障碍 — 连续错误触发

**交互**：
- 点击阶段 → 右侧切换到该阶段详情
- 展开/折叠章节列表
- 当前阶段默认展开并高亮

   影响：阶段3预计完成时间推后1天

            时间约束：10个有效学习日（周末休息）

每条调整日志的字段：
- `时间`
- `类型`（加速/障碍/插入/拆分/冲刺/初始化）
- `原因`（用自然语言解释触发条件）
- `变化`（具体改变了什么：天数、顺序、任务）
- `影响`（对整体计划的影响）

## 4. 关键交互流程

### 4.1 用户完成一个任务

```
用户点击任务的 ☐ → ☑
  → 前端乐观标记完成
  → 调 PATCH /api/learning-path/nodes/:id { status: "completed" }
  → 后端检查该阶段是否全部完成
    → 是 → auto_advance 到下一阶段
    → 否 → 仅更新 mastery
  → 后端返回更新后的阶段数据
  → 前端合并更新，不重新拉全量路径
```

### 4.2 用户做完练习题（从 Lecture 页面回来）

```
用户在 Lecture 页提交了小测
  → 后端 assessment 触发 post_quiz_assessment
    → diagnosis_agent 更新诊断
    → planner_agent.run(mode="adjust") 调整路径
  → 后端存储新路径，递增 pathVersion
  → 前端轮询或 SSE 检测到 pathVersion 变化
  → 前端 diff 新旧路径，展示调整动画
  → 调整日志区新增一条记录
  → 如果阶段结构变化（新增/删除/重排），页面平滑过渡
```

### 4.3 用户说"调整一下"

```
用户在聊天框说"我觉得极限太难了，放慢一点"
  → ConversationAgent 解析意图
  → 设置 plan_mode="adjust" + 附带用户约束
  → orchestrator 正确翻译为 mode="adjust"（修 Bug）
  → planner._run_adjustment() 以用户约束为额外输入
  → 返回调整后的路径 + adjustments 日志
  → 前端更新路径，日志区高亮新记录
```

### 4.4 用户手动干预

```
用户在某个阶段卡片上：
  [跳过此阶段] → 弹出确认："这个阶段的知识是后续阶段的前置，跳过可能影响学习效果。确认跳过？"
  [增加天数]   → 弹出滑块："从3天增加到___天（最多5天）"
  [拆分阶段]   → "将这个阶段拆成2个子阶段？"

手动干预也生成一条调整日志，标记为 [用户手动调整]
```

### 4.5 全局开关

```
TOP BAR 上的 [暂停自动调整] 开关：

默认开启：系统持续监控学习数据，自动调整路径
关闭后：路径冻结为当前状态，不再自动变化
        关闭期间做错题/超预期 → 不触发 adjust
        重新开启时 → 立即基于当前最新数据做一次全量调整

适用场景：用户考前冲刺不想被打乱计划
```

## 5. 状态与动画

### 5.1 阶段变化动画

| 变化类型 | 动画效果 |
|---------|---------|
| 阶段加速（天数缩短） | 进度条加速流动 + 天数数字缩小动画 |
| 阶段减速（天数增加） | 进度条减速 + 天数数字变大 + 后续阶段下沉 |
| 新阶段插入 | 列表裂开 + 新卡片从透明滑入 + 后续卡片下移 |
| 阶段完成 | ✅ 图标弹跳 + 卡片整体变绿 + "进入下一阶段"按钮出现 |
| 遇到障碍 | 阶段卡片边框变橙 + 顶部警示条展开 |

### 5.2 调整通知

调整发生时，无论用户在哪个页面，右上角弹出 Toast：

```
┌────────────────────────────────┐
│ ⚡ 学习路径已自动调整            │
│ 阶段2提前完成，整体进度加快1天    │
│ [查看详情]          [×]        │
└────────────────────────────────┘
```

Toast 3秒后自动消失，不中断当前操作。「查看详情」点击后跳转到路径页面并滚动到对应日志。

## 6. 数据结构约定

### 6.1 后端返回的 LearningPath 增加字段

```typescript
interface LearningPath {
  // === 现有字段 ===
  stages: Stage[];
  estimatedDays: number;
  planSummary: string;
  // ...

  // === 新增字段 ===
  pathVersion: number;           // 每次 adjust 递增，前端据此判断是否需要 diff
  adjustments: Adjustment[];     // 调整日志（最近的 N 条，全量存在后端）
  createdAt: string;             // 首次生成时间
  updatedAt: string;             // 最后调整时间
  autoAdjustEnabled: boolean;    // 是否开启自动调整
  remainingDays: number;         // 剩余天数（根据实际进度重新计算）
}
```

### 6.2 调整日志条目

```typescript
interface Adjustment {
  id: string;
  timestamp: string;
  type: 'init' | 'accelerate' | 'decelerate' | 'insert' | 'split' | 'reorder' | 'sprint' | 'manual';
  reason: string;               // 自然语言原因
  changes: {                    // 结构化变更描述
    stageId?: string;
    before?: { days?: number; title?: string; };
    after?: { days?: number; title?: string; };
  };
  impact: string;               // 对整体计划的影响
  triggeredBy: 'auto' | 'manual' | 'quiz_result';
}
```

## 7. 实施优先级

| P0 — 没有这个就不是"动态" |
|---------------------------|
| 修 Bug：plan_mode="adjust" → mode="adjust" |
| 前端轮询 pathVersion 或 SSE 订阅路径变化 |
| 调整日志区（展示 adjustments 数组） |

| P1 — 让"动态"对用户可见 |
|-------------------------|
| 阶段卡片展示掌握度 + 做题统计 |
| 调整通知 Toast |
| 阶段变化动画 |

| P2 — 让用户能主动控制 |
|-----------------------|
| 暂停/恢复自动调整开关 |
| 手动干预（跳过/增加天数/拆分） |
| 调整日志筛选（只看自动/只看手动/只看障碍） |

| P3 — 体验优化 |
|--------------|
| 知识点掌握度明细雷达图 |
| 路径预测："按当前速度，预计X天后完成" |
